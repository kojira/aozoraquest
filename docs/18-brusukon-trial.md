# ブルスコンの試練 (ミニゲーム)

あおぞらパワーを消費して遊ぶターン制バトルのミニゲーム。ブルスコン (召喚済みの精霊)
が「試練の使い」として SVG モンスターを召喚し、プレイヤーはジョブの特性を活かして戦う。

**精霊チャット (LLM 会話) はこの機能で置き換えて廃止する** (オーナー決定 2026-07-17)。
過去の spiritChat レコードは消さない (パワー式の userMessages は従来どおり数える =
残高が急に増えない)。

## 経済

- 1 戦 = あおぞらパワー **1** 消費 (`BATTLE_TUNING.powerCost`)。
- パワー残高式は `viaPosts − userMessages − cardDraws − battles` に拡張する
  (`app.aozoraquest.power/self` に `battles` カウンタを追加。旧レコードは欠落 → 0 扱い)。
- 勝利でパワーは**返さない** (インフレ防止)。報酬は XP / 戦績 / 称号 / 素材ドロップ。
- 挑戦条件: ブルスコン召喚済み (従来の SUMMON_THRESHOLD ゲートを流用)。
- **1 日の挑戦上限 = 10 回** (`TRIAL_DAILY_LIMIT`、JST 暦日区切り。オーナー要望
  2026-07-18)。上限は試練 (`source='trial'`) のみで、あおぞらワールドの野外遭遇
  (`source='world'`) は対象外。カウントは battle レコードをその日ぶん集計 (専用
  カウンタは持たない)。途中離脱 (棄権) も仮レコードが残るので 1 回と数える。
  実装は `apps/web/src/lib/trial-limit.ts`。**W3 (Worker/DO 権威化) 時に上限判定を
  サーバへ移す**まで、複数端末同時挑戦の厳密な超過防止はできない (クライアント
  自己申告のため数回超過し得る。パワー消費は正しく引かれるので無料無制限ではない)。
  その際は `TRIAL_DAILY_LIMIT` を core tuning へ移す想定。

## バトルエンジン (packages/core/src/battle.ts)

- **決定的**: seed + コマンド列から結果が一意。乱数はターン毎に `hash(seed, turn)`
  から生成するので state は JSON 化できる (テストで挙動を固定できる)。
  ※ battle レコードにはコマンド列は残さないため、記録から勝敗を再現・検証すること
  はできない。記録の目的は消費の記帳と戦績集計。
- プレイヤーの戦闘値は**プロフィールの個人 5 パラメータ (rpgStats、合計 100) を
  ジョブ基準値と 50:50 でブレンド**した基底から導出 (`playerCombatant`)。個人値
  100% は診断の min-max 正規化 (全員が必ず極端プロフィールになる) で勝率が 0〜100%
  に割れたため (issue #279 実測)、ジョブの型を保ちつつ個人の傾きを乗せる。未診断は
  ジョブ基準値のみ。
- レベル補正は乗算 (jobLv +4%/Lv, playerLv +1.5%/Lv) に加えて**平坦な加算成長**
  (+0.25 × (playerLv−1) を全ステータスに。レベル係数の乗算前に加算するので実効値は
  係数分だけ大きい)。乗算だけだと低い値は低いままで「弱いジョブがレベルで
  ちゃんと強くならない」(オーナー指摘 2026-07-17)。**モンスターにも同量の加算**を
  与えて比率を保存する (プレイヤーだけだと高レベル帯で tier3 が作業化する)。
- luk は ①gamble ダメージ基準 ②下振れ床 ③クリティカル率 ④ドロップ率 の 4 箇所に
  効く (支配ステータス基準化の帰結)。W6 の装備設計は「luk 盛り = 火力と経済の
  両取り」を前提に組むこと。
- **特技はジョブの支配ステータスで決まる** (技名はジョブ固有 `JOB_SKILL_NAMES`):
  | 支配 | kind | 効果 (**ダメージ基準値は支配ステータス**) |
  |---|---|---|
  | atk | smash | 1.7 倍撃・少し外れやすい (atk 基準) |
  | def | parry | 防御 + 被弾時に反撃 (**反撃は def 基準**。行動順に関係なくターン頭で構える) |
  | agi | flurry | 0.65 倍 × 2 回攻撃 (**agi 基準**) |
  | int | spell | 防御半減貫通・必中 (int 基準)。硬い敵に有効 |
  | luk | gamble | 0〜2.6 倍・luk が高いと下振れしにくい (**luk 基準**) |

  特技のダメージ基準を atk 固定から支配ステータスに変更 (2026-07-17。「能力が
  ジョブに合っている」— luk/agi 型が atk 7〜9 のせいで何をしても火力が出ず、Lv1 の
  5 連戦生存率が bard/paladin 0% だった sim 実測への対応)。タイ (artist の
  def=luk=26) は後勝ちで gamble。
- **MP 回復のジョブ特性** (`JOB_MP_TRAITS`。オーナー提案 2026-07-17): 戦闘中に
  MP が回復するのは**特性を持つジョブだけ** (基本回復は廃止 — オーナー決定
  「ジョブの差がぼやけてしまう」)。素の火力が低く特技依存の弱ジョブに世界観に
  沿った特性名で回復を与える:
  | ジョブ | 特性名 | たたかう | ぼうぎょ |
  |---|---|---|---|
  | bard | 歌の余韻 | +3 | +4 |
  | paladin | 祈りの加護 | +3 | +4 |
  | miko | 神楽の集中 | +2 | +3 |
  | poet | 心晴の呼吸 | +2 | +3 |
  | explorer | 踏破の勘 | +2 | +3 |
  | ninja | 印の呼吸 | +2 | +3 |
  | artist | 色彩の集中 | +2 | +3 |
- コマンドは たたかう / とくぎ / ぼうぎょ / やくそう / そらのしずく / にげる の 6 択
  (スマホ縦 2x3 の大ボタン)。
  **どのコマンドにも存在意義がある**よう設計する (オーナー指摘 2026-07-17 への対応):
  - **MP 制**: とくぎは MP 4 消費。最大 MP は int から導出 (mpIntScale 0.5。
    int 職は手数 = プールが大きいのがアイデンティティ)。**戦闘中の MP 回復は
    ジョブ特性を持つジョブだけ** — 特性なしジョブはプールとそらのしずくで
    やりくりする (全員一律回復はジョブ差をぼやけさせるためオーナー決定
    2026-07-17 で廃止。ワールドでは MP が戦闘をまたぐので、回復手段は
    街・しずく・特性の 3 択になる)。
  - **ぼうぎょ**: 被ダメ半減 + **翌ターンまで回避 +15%** (身構えて動きを読む)。特性ジョブは MP も回復。
  - **ため予告**: tier2+ の敵は強攻撃の前に「力をためている…!」と 1 ターン予告
    (そのターン攻撃なし)。次ターンのため攻撃は 2.6 倍 — 予告を見て防御すれば 1.3 倍
    (節約 1.3 発分 > 機会費用 1 発分) + 回避チャンス。読み合いの核。
  - **やくそう**: tier1/2 がドロップ。最大 2 個持ち込み、使うと HP 30% 回復 (1 ターン)。
    「防御で凌いで → やくそうで立て直す」が成立する。使用数は battle レコードの
    herbsUsed に記録し、在庫 (素材集計) から差し引く。
  - **そらのはね** (帰還アイテム、ワールド用): コウモリ 0.12 / おおガラス 0.25 が
    ドロップ。戦闘では使えない (フィールド専用。docs/19)。
  - **そらのしずく** (MP 回復薬): ヒカリダケ/鬼火/おおガラスがドロップ。最大 2 個
    持ち込み、使うと MP 50% 回復 (1 ターン)。使用数は tonicsUsed に記録し在庫から
    差し引く。MP 回復が特性限定になったため、特性なしジョブの主要な戦闘内
    MP 回復手段でもある。あおい鬼火のやくそうドロップ (0.2) はしずくに差し替えた (tier2 の
    やくそう供給は golem/serpent に残る。しずくの主用途はワールドの MP 持続)。
  - **にげる**: 成功率 = 50% ± agi 差 ×1.2%/pt (25〜95% にクランプ)。成功すると
    outcome=fled で離脱 (XP・ドロップなし、パワーは返さない)。失敗するとターンを
    失い敵の攻撃を受ける。fled は連勝を切るが敗北には数えない。
- モンスターは tier 1〜3 (手習い/修練/真剣勝負) × 各 3 種。プレイヤーレベルに追随して
  スケールし、tier 係数は 0.72 / 1.1 / 1.36 (「序盤の敵が強すぎる」オーナー実感
  2026-07-17 → tier1 を 0.85 から緩和。Lv1 の tier1 5 連戦生存率が全ジョブ 86〜100%
  になる水準を scripts/sim-battle-balance.ts で実測)。モンスターは playerLevel に
  加えて jobLevel も 1/4 だけ追随 (monsterJobChaseScale 0.01。追わないと jobLv20 で
  tier3 が全ポリシー 100% = 作業化)。**運用想定帯は 〜plLv20/jobLv10** — それ以降は
  熟練の優位が増して tier3 勝率が 95% 超に達するため、W6 (装備・新コンテンツ) で
  再設計する。バランスはテストで固定: Lv1×tier1 全ジョブ単戦 ≥80%、高 Lv×tier1
  勝率 ≥80%、Lv1×tier3 敗率 ≥60%、tier3 天井 (複数ポリシーの最大で <94%)。
- **モンスターの行動バリエーション (2026-07-18、オーナー要望)**: 全モンスターが
  ため攻撃する状態をやめ、種別ごとに行動タイプを持たせて戦略性を出す。
  MonsterDef.ability: 未指定=plain (通常攻撃 + 低 HP でたまに防御) /
  'charger' (1 ターン ため → 強攻撃。予告を防御する読み合い。全 9 種中 2 種 = ~22%) /
  'healer' (低 HP で自己回復。削り切る読み合い)。
  **モンスターも int から MP を持ち (fromStats。以前から算出済みだが未使用だった)、
  ため/回復に MP を消費する** (`monsterChargeMpCost` 5 / `monsterHealMpCost` 7)。
  int の高い敵ほど特技を多用でき、尽きると通常攻撃に落ちる = MP を削り切る/尽きるのを
  待つ資源の読み合い (オーナー提案「モンスターに MP ないの?」)。UI は charger/healer の
  MP バーを敵の下に表示 (「ためる力 / かいふくの力」)。
  割り当て: tier1 全 plain / tier2 golem=charger・wisp=healer・serpent=plain /
  tier3 oni=charger・dragon=healer・raven=plain。
  設計メモ (レビュー): 実難度で最も厳しいのは healer より **charger (oni) × 低火力
  低 agi の def タンク** (手数で押し切られる) だが、tonics/herbs 込みの本則プレイでは
  破綻せず快適帯に収まる。healer は「低火力ジョブほど回復回数を許す」= タンクが
  やや苦戦する相性 (意図的。フル装備で 95%+ に戻る)。tier1 が全 plain なのは
  「初戦は必ず勝てる」設計と両立 (ため/回復の読み合いは tier2 から登場)。
  戦闘 UI は charger/healer の「あと何回撃てるか」をセグメント (charger=橙/healer=緑)
  で表示し、資源を読んで押し引きできるようにする。
- **見切り (parry) の再測定 + 調整 (同 2026-07-18)**: モンスター変化で「ためない敵」が
  増え、見切りは能動的に構えるのが最適 (通常攻撃も反撃で捌く) と判明。sim の方針を
  能動的見切りに修正したところ def タンク (warrior/guardian) が過小評価されていたと分かり
  (フル 99.8% = 作業化)、見切り反撃倍率を 1.2→0.75 に調整。結果、装備込み分布は
  **裸 tier3 = 31〜82% (中央 64) / フル = 83〜97% (中央 93)** で「装備なし=挑戦的 /
  フル=快適」の帯を維持。
- 30 ターンで強制判定 (残 HP 割合勝負)。
- **装備込みバランス調整 (2026-07-18、リリース必須要件 #6)**: 「装備なし = 挑戦的 /
  フル装備 = 快適」を狙い、`scripts/sim-all-jobs.ts` で全 16 ジョブ tier3
  (jobLv8/plLv15、各 N=400、フル装備 = 専用上位武器 + そのジョブが着られる最良防具
  + いのちのペンダント) を実測して再調整。調整前は **def が生存 (HP + 被ダメ軽減) を
  二重支配**し、def の高い warrior/miko/poet が裸で 80〜88% (作業化)・def の低い
  shogun/ninja/bard が裸 15〜33% (壊滅) と両極端だった。def 依存を下げて生存の底を
  上げる方向で `hpBase` 46→66 / `hpDefScale` 0.9→0.32 / `damageSoften` 14→26 /
  `damageScale` 26→30 / `agiDodgeScale` 0.006→0.009 / `dodgeMax` 0.25→0.32 に調整。
  結果、**裸 tier3 = 22〜80% (中央 53) / フル装備 = 76〜97% (中央 92)** に圧縮
  (弱ジョブ救済 bard: 裸 33→47 / フル 72→85、shogun: 裸 17→22 / フル 67→76、
  上位の作業化解消 miko: フル 98→95 / warrior: フル 99→96)。shogun は **裸 def 10**
  の意図的な glass cannon (裸 22% / フル 76% = 装備前提。上位武器が def+7/HP+14 を
  複合で補う)。`chargedPower` は 2.6 据え置き (予告→防御が正解の設計を維持。ただし
  被ダメ再調整で tier3 の防御の旨味は相対的に痩せた — 追跡 issue)。

## 記録 (PDS)

- `app.aozoraquest.battle` (tid rkey): 1 戦 1 レコード
  `{ seed, tier, monsterId, outcome, turns, drops, herbsUsed, tonicsUsed,
  materialsLost, at, via }` — 消費の監査 + 戦績/称号/素材の集計ソース。outcome は
  win/lose/draw/fled。materialsLost はワールドの敗北ペナルティ (docs/19) で、
  仮レコード時点で確定値を書く (途中離脱 = 棄権でもペナルティが効く)。
- `app.aozoraquest.power/self`: `battles` カウンタを増分 (bumpPower 拡張)。
- 集計 (`wins/losses/bestStreak/tier3Wins`) から称号 (`TITLES`) を導出。

## SVG モンスター

species キー (slime/bat/mushroom/golem/wisp/serpent/raven/oni/dragon) ごとに
UI 側でインライン SVG を描く。画像アセットなし = 軽量・省メモリ (モバイル方針)。

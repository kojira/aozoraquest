# #675 岸辺オートタイル

## 承認・入口・成果
ユーザー参考画像を確認。既存画風のオリジナルpixel artで、水を塗るだけで海岸・池が丸くつながる方式（親承認範囲）。画像の切り出しはしない。
- `/admin/map` の地図タブ、または `/admin/interiors` でマップを選ぶ → 既存の「海」/「池」パーツを塗る → その場で岸辺をプレビュー → 明示「保存」→ 再読込 → `/world` で同じ表示。フィールドに置いた水も内部に置いた水も対象。
- 個別の絵が登録されている水は従来どおりその絵を優先。標準岸辺は同梱絵にのみ適用。既存マップもデータ変更なしで標準水の表示が変わる。再保存や自動変換は不要。
- 外洋の地形生成・マップのサイズ・通行判定・池の通行性は変えない。マップ全体図（1マス1画素）、NPC配置の補助地図、絵そのものの編集画面は従来表示のまま。本件は地形配置editorとゲームの詳細タイルが対象。

## 設計（実装前）
既存16×16ドット絵を32×32 SVGで表示する方式とdefs/use共有を維持。web内の純粋な岸辺解決/画素生成モジュールとworld-tilesの描画関数を追加し、既存3画面へ接続。core/API/schema変更は不要。

水系は `water` / `pond`、接続先には `bridge` も含む（橋を塗り替えない）。中心が標準水のとき8近傍を調べ、四隅それぞれを8×8 quarterとして解決する。2直交隣接が水なら対角が水で中央、水でなければ陸の出角。両方陸なら水の丸い出角、片方陸なら直線岸。四隅合成なので1マス池・細水路・岬・入り江・対角分離を同じ5型で表現できる。基本13種は見本分類であり全接続パターンではない（正規化47組合せ）。水セル内に草・土・明るい水際を描き、陸セル/施設/個別アートには描き足さない。水面は既存同梱waterの色/波に合わせ、岸のパターンは新規作画。

`tileArtTerrains()` の既存登録キーを参照し、地形キー/パーツキーが未登録の標準水だけ対象にする。画素の一致推測をしない。独自partsの内部では既存と同じ地形名参照のみ。岸辺maskをdefs keyに含め、異なる接続が同じ絵を共有しないようにする。パレットアイコンは従来の単体絵。フィールドeditorは保存前draft全体の近傍から計算し、worldは実地形から計算。viewport外の1マスも見る。フィールドはwrap、内部範囲外は水の継続として描く（端に架空の草岸を作らない）。内部の範囲外自体は従来どおり壁で表示する。

## 不変条件と失敗
保存経路・ボタン・読み込みgate・権限・ゲート・NPC・進捗・報酬は変更しない。岸辺maskは永続化しない。失敗/競合/再試行は既存保存契約のまま。PDSへの実書込は禁止。配備/main/dev mergeは後続レビュー後の親担当。復旧はweb変更のrevertのみ。

## 実装中の設計補足（親承認済み）
フィールドeditorの既存表示が `BASE_PALETTE[idx]` 固定だったため、増設した水/橋を中心・近傍として正しく判定できないことを実ソースで確認。親へ相談し「今回の接続整合に直接必要な表示解決のみ」の修正を承認された。実parts[idx].terrainを既知地形の範囲で解決し、未知値はworldと同じplainsへ倒す。保存/通行/個別アート優先は不変。増設水・橋を代表マップへ入れ、field editorのプレビューとWorld表示の一致を追加受入とする。別のpalette問題への汎用修正はしない。

## 検証結果・境界
- 434 web unit tests / typecheck / build成功。lintは既存警告24件・エラー0。
- Chromium: 実内部editor（独自partsの水index1/池index2）で塗る→プレビュー→明示保存→reload→実Worldの岸辺画素一致。保存gzipは操作したtilesだけで、別マップ/partsを保持。
- 実field editor: 増設water/bridgeを1023↔0の境界に配置した隔離recordで、接続を確認→池を追加→保存→reload→実World一致。保存前put無し・parts保持も確認。
- 比較図/基本13分類の画像を生成し、丸い角・入り江・細水路・対角池を目視。実機Safari・認証付きdev gameplayは未検証。
- E2Eの初回はfixture API pathの`/api`不足でWorld位置復帰が失敗、次の追加field検証はfixtureの英語パレット名に対して日本語selectorを使い失敗。fixtureだけを修正して3件成功。アプリ失敗を隠す変更や実ネットワーク接続はなし。
- 範囲外既存問題は #676 に分離：内部mapでpartsを省略したまま共有増設indexを使うと、coreはBASE_PALETTEで解決するがeditorの既存絵は共有parts参照。core地形/通行契約は今回変更せず、editorの既存fallbackも保持した。内部の自動岸辺は基本water/pond、または明示partsを持つマップで使える。fieldの増設水は本件で対応済み。

## 確認手順（配備後）
1. `/admin/interiors` でマップを選ぶ。海/waterまたは池/pondを塗る。隣接マスと岸がつながる。
2. 「保存」、再読込して同じ形を確認。ゲームはそのマップへ入り直して確認。保存反映は既存案内どおりサーバー最大5分。
3. 外洋は `/admin/map` の「地図を編集」で同様。既存標準水は表示だけ自動更新されるので再保存不要。
4. 個別の絵を描いてある水は変わらない。既存の「同梱の絵に戻す」はユーザーが明示選択する操作であり、本機能が自動実行しない。

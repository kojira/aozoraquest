# あおぞらワールド (2D オーバーワールド) 仕様書案 — 第 2 部 ([目次](./19-overworld.md))

## 6.5 戦闘の強度モデル (固定強度 — オーナー要望 2026-07-20)

**敵はプレイヤー/ジョブレベルに追従しない = tier (エリア) 固定強度**。
「自分の強さに合わせて敵も強くなるのはダメ (やるとしても終盤エンドコンテンツ)」。

- `monsterLevelFactor(def)` は敵の想定レベルと tier のみ (#536)。旧実装にあった playerLevel/jobLevel 追従と、
  モンスターへの `flatLevelGain` 加算は**撤廃**した。
- **tier = そのエリアの「想定プレイヤーレベル」** (`TIER_LEVEL = {1:1, 2:10, 3:20}`、#518)。
  モンスターの `stats` は職と同じ**合計 100 の比率**なので、プレイヤーと同じ成長式
  `statFloor + 比率 × (statBase + statGrow × (Lv−1))` に載せないとスケールが噛み合わない。
  tier をレベルで表すことで、プレイヤーの成長レンジ (Lv1→30 で約 8 倍) と同じ幅を tier 側も
  持てる。**これは「敵がプレイヤーに追従する」ことではない** — tier はエリアに固定で、
  プレイヤーが伸びれば既存エリアが楽になる性質は変わらない。
- `MONSTER_POWER = 0.5`: モンスターの profile は utility (int/luk) に予算を割く必要がない
  ぶん atk に偏る (あおおには 126 中 66 = 52%、戦士は 100 中 25 = 25%)。同じ倍率で並べると
  殴り合いが 2 ターンで終わる大味な戦闘になるため、profile の形は保ったまま出力だけを
  職と同水準に均す。
- モンスターの HP も `hpBase + hp × 成長率 × hpVitScale` に載せる (`hp` を職の vit と同じ
  「たいりょく相当の生値」として扱う)。旧実装は `hp` をそのまま絶対 HP にしていたので
  tier2 (22〜28) → tier3 (24〜30) とほぼ伸びず、上位 tier ほど瞬殺されていた。
- 同じ敵は Lv1 でも Lv30 でも強さが同一 (HP/atk/def/agi/int/luk/MP)。プレイヤーが伸びれば
  既存エリアは**相対的に楽になる** = 成長が報われる。
- **後半の難易度は「レベル追従」ではなく「エリアごとに強い敵を配置」で作る** (出現セット/
  エリア設計は後続 PR)。終盤エンドコンテンツで追従を戻すなら tier 限定で `monsterLevelFactor`
  に足す。
- **撤廃した旧監視項目** (docs/18 に記載があった「高 Lv で tier3 が作業化しないよう追従で
  釣り合いを取る」「tier3 天井 <94%」等) は、固定強度では**意図的に不採用**。outleveling で
  楽になるのが正しい挙動。

**過渡期リスク (エリア設計 PR が入るまで)**: tier2/3 も固定強度なので、レベルを上げると
全 tier が楽になる (sim: plLv20 で tier1/2/3 とも 5 連戦生存 ~100%)。逆に低レベルで高 tier に
入ると即死 (plLv1×tier3 = 0%)。後半エリアの再ハード化 (強い敵の配置) と、アンチファーム
(強くなると弱い敵は逃げる / XP カーブ) を後続で積んで回収する。危険領域の視認性・進入警告は
別 issue。

## 6.6 入口の難易度は「街を出てから何戦もつか」で測る

勝率ではなく**連戦数**を指標にする。街は全回復地点で、HP・MP・やくそうは戦闘をまたいで
持ち越し、瀕死なら野外でやくそうを飲む。「1 戦の勝率 90%」でも回復が尽きれば 3 戦で
死ぬので、勝率だけ見ていると入口の体感を取り違える。

計測: tier1 / Lv1 / 装備なし / 全 16 職 × 30 試行 / `runAutoBattle`。

| | tier1 Lv1 裸 | tier2 Lv5 布の服 | tier3 Lv9 旅の外套 |
|---|---|---|---|
| `monsterStatFloor` 6 | 2.25 戦 | — | — |
| **3 (採用)** | **7.24 戦** | 17.81 戦 | 7.87 戦 |

再現: `pnpm --filter @aozoraquest/core sim:endurance` (`TIER` / `LV` / `GEAR` で条件を変える)。
**スクリプトが repo に無いと引き直せない**ので、`scripts/sim-endurance.mts` に置いてある。

`monsterStatFloor` はモンスター側の下駄 (プレイヤーの `statFloor` とは別値)。
実効値は `round(下駄 + 比率 × tier係数)` の**加算**なので、tier係数の小さい入口ほど効きが
大きい (tier1 で atk 7→4 = 1.75 倍の緩和 / tier6 では 50→47 = 1.06 倍)。
つまり**構造的に入口専用のつまみ**で、帯ごとの強さは `TIER_STRENGTH` が別に持つ。

**3 を採ったのは、入口 (7.24) と中盤 (7.87) がほぼ揃うから** — 4 だと入口 4.65 に対し
tier3 が 5.84 で、**入口が一番きつい**という逆転が残る。
tier2 が緩い (17.81) のは「最初の防具を買えた直後」の帯なので、意図どおり息継ぎになる。

**この水準はオーナー判断に返す項目** (#536)。2026-07-26 に「平均 4.4 戦」として提示した
数値はハーネスの不備で実際の約 2 倍だった (真値は下駄6 = 2.25 戦)。dev のベースライン
(2.79 戦) も測っていなかったため、「緩める」指示に対して逆に厳しい方を提示していた。
上の表は dev と同一ハーネスで測り直したもの。

## 8. 判断ログ (2026-07-17 オーナー回答)

1. **移動コスト**: 1 歩 = 1 パワー厳守 (ヘビーユーザーは 1 日 100 投稿 = 100 歩)。
2. **敗北**: 最寄りの街戻りのみ。
3. **店**: 街ごとに品揃えが違う。地域モンスターに効く (特効) 装備を売る。
4. **街に固有名を付ける** (§3)。
5. **Durable Objects の課金試算** (2026-07 時点の CF 料金で):
   - DO は **Workers Free プランでも利用可** (SQLite-backed)。無料枠は
     リクエスト ~300 万/月・compute 約 39 万 GB 秒/月・ストレージ 5GB
     (Free プランはストレージ課金なし)。
   - 本機能の負荷: 1 歩 = 1 パワー = 1 投稿相当なので、ヘビーユーザーでも
     ~100 歩/日 = 100 リクエスト/日/人。戦闘もサーバー解決 (1 ターン 1 リクエスト)
     で、遭遇 ~10 戦/日 × ~10 ターン = +100 リクエスト/日/人。**合計 ~200/日/人**。
     アクティブ 100 人でも 2 万 req/日 ≈ 60 万/月 = **無料枠 (~300 万/月) の 20%**。
     DO はハイバネーションで待機中は compute 課金されず、保持するのはカウンタ +
     座標 + 進行中 BattleState (~1KB)。
   - **結論: 想定規模では追加課金 $0** (無料枠内)。有料プラン ($5/月) でも
     込み枠が桁違いに大きく増額なし。アカウントのプラン種別だけ実装時に確認する。

## 6.7 地形は「1 タイル 1 バイトの地図」で持つ (#421)

地形は `baseTerrainAt` が 1024×1024 をノイズから毎回計算していた。マップエディタで
手編集するには差分を持つしかないが、**疎な差分は上限が要り**「広い面積を塗ると
保存できない」「上限超過で断る」「部分適用しない」という問題を丸ごと抱える。

**画像として持てば塗り放題で、しかも小さい** (実測):

| | 値 |
|---|---|
| 生バイト (1 タイル 1 バイト) | 1,024 KB |
| gzip 圧縮後 | **27.2 KB** |
| gzip 展開 | 0.6 ms |
| 読み込み全体 (base64 → 展開 → 配列) | 8 ms |

副産物として**速くなる**。`terrainAt` はノイズ計算 3.27 µs/回 に対し、地図があれば
**0.060 µs/回** (約 55 倍)。全域スキャン 3.3 秒が不要になり、edge の CPU 時間にも効く。

```
terrainAt = 地図 (画像) ?? overlay (街/橋) ?? base (ノイズ生成)
```

### 決めごと

- **パレットは 1 バイト = 256 種**。地形は増える前提なので 8 種に固定しない。
  index → 地形 id はデータとして持ち運ぶ
- **知らない index / 知らない地形 id は `fallback` に倒す**。エディタで新地形を足した
  瞬間、まだデプロイされていない edge / web がそれを読むタイミングが必ずある。
  そこで落ちたり通行判定が狂うと**プレイヤーがその場から動けなくなる**
- **既知の 8 種は index 0〜7 に固定。並びを変えない** (変えると既存地図が全部ずれる)
- **保存形式は PNG ではなく生バイトの gzip**。Cloudflare Workers に PNG デコーダが無く、
  gzip は `DecompressionStream` が標準で使えて依存ゼロのため。
  外部の絵描きツールで描きたい場合は**エディタ側だけ** PNG 入出力に対応させる
- **パレットは色も持つ** (`TERRAIN_COLORS`)。地形を増やすと必ず「パーツ (タイルの絵) が
  要る」問題が出るが、絵が揃うまで編集を始められないのは困る。**色だけ決めれば
  地図もエディタも動く**ようにしてある。絵は後から差し替える
- 同梱の地図 (`pnpm gen:world` が生成) は**ノイズ生成 + 街/橋の overlay を焼き込んだもの**。
  読み込んでも見た目は 1 ピクセルも変わらない (**全 1,048,576 タイルで差分 0**)。
  **街と橋を焼き込むのは必須** — `baseTerrainAt` の戻り値型は `Exclude<Terrain, 'town'|'bridge'>` で
  原理的に入らず、地図は overlay より優先されるので、焼き込まないと
  **橋が water になって渡れず、街が平地になって入れなくなる** (103 タイル)。
  抜き取り検査では見つからない (差分率 0.0098% なので 5,000 点だと期待ヒット 0.49)
- **読み込むまでは従来のノイズ生成に倒れる**ので、待たずに遊べて結果も一致する

### 残っていること

- 編集した地図を管理者 PDS に保存し、**edge が読む**配線 (移動判定は edge が権威なので、
  web だけに置くと「画面では歩けるのにサーバーが弾く」= その場から動けなくなる)
- 保存前の到達性検証 (§1 の「spawn から歩行可能タイルの 95% 以上に到達できる」保証)
- 街の編集 (追加・移動・削除)。**街を 1 タイル動かすと店の品揃えが全部変わる**
  (`townShopStock` は街の x/y をシードにした純関数) ので、エディタ側で明示する

### タイルの絵はドット絵をデータで持つ

タイルの見た目は `world-tiles.tsx` の SVG を**コードに直書き**していた。地形は 256 種まで
増える前提なので、増やすたびにコードを書くのは続かない。**エディタで描いたドット絵を
データとして持つ**ようにした (`tile-art.ts`)。

- 1 タイル = `size × size` の画素で、各画素は**タイル内パレットの索引 1 バイト**。
  **色そのものを画素に持たない**のは、パレットを差し替えるだけで夜・雪・毒沼のような
  色調を、絵を描き直さずに出せるようにするため
- 16×16 なら 1 地形 ~370 バイト。**256 地形ぜんぶ描いても ~93 KB**
- 描画は **ドット絵 → 従来の SVG → 代表色のべた塗り** の 3 段で倒れる。
  地形を増やすと必ず「絵がまだ無い」状態を通るので、そこで描画が止まらないようにする
- 画素は `<rect>` の並びで出すが、**同じ色が続く区間は 1 本にまとめる**
- **`shape-rendering: crispEdges` でアンチエイリアスを切る (ドット絵の作法)。**
  既定の描画では矩形の境界が補間され、隣り合う画素の間に**中間色のスジ**が入る。
  縮小時 (16px 表示など) は 1 画素が 1 デバイス画素を割り、補間で**潰れて別の色**になる。
  実機の 24px / 16px 表示で実際に発生した。最近傍に倒せばどの倍率でも画素のまま出る

**エディタは専用画面 (`/admin/map`)** にする。管理ダッシュボードの「マップ」カードから飛ぶ。
地図は広く縦に長いので、他の管理ツールと同居すると双方が使いにくい。

**色を塗るのではなく、パーツを置く。** 1 タイル 1 画素で色を塗る形にしていたが、
**1 ドットに対する操作は現実的でない** (何を塗ったか見えない / どの色がどの地形か
分からない)。ワールド画面と同じ**タイルの絵をそのまま並べて置く** (16〜48px を選択)。
内部の持ち方は変わらず 1 タイル 1 バイトなので、置いた瞬間に 1 バイト書くだけ。
**グリッドを重ねる** (8 タイルごとに濃くして座標を数えられるようにする)。

**操作は地図の上に重ねる。** 十字キーと「ためす / みんなに反映」を地図の下に並べると、
1 マス置くたびに画面をスクロールして戻る羽目になる (実機で指摘)。

**文字選択を止める。** 地図をドラッグすると近くの説明文が選択され、iOS では選択が
解除できず**保存ボタンも押せなくなる**ところまで行った (実機で発生)。
`user-select: none` と `pointerdown` の `preventDefault` の**両方**が要る
(片方だけだと環境によって選択が残る)。

当たり判定は**タイルごとの透明な矩形をグリッドより後ろに敷く**。絵の中の要素で
拾い漏らすと「置けないタイルがある」、グリッドが手前だと「線をなぞると筋状に抜ける」
という分かりにくい壊れ方をする。

**「ためす」と「みんなに反映」を分ける。** 編集はコピーの上で行うので、置いただけでは
`/world` に出ない。「ためす」は読み込み済みの地図と差し替えて**自分のブラウザでだけ**
歩いて確かめられる状態にする (他人には見えず、リロードで戻る)。「みんなに反映」が
管理者 PDS への保存で、ここで初めて全員とサーバーに配られる。

**編集はコピーの上で行う。** `worldMapTiles()` が返すのはモジュールグローバルの実体で、
SPA では core が単一インスタンスなので、そこを直接書くと**管理画面を開いて塗っただけで
ワールドの地形が変わる** (自分の現在地を水にすると身動きが取れなくなる)。
「この端末に反映」を押したときだけ `setWorldMap` する。

**編集画面の色は地図の色と別**にする (`EDITOR_TERRAIN_COLORS`)。地図側は plains と town、
pond と water が同色 (街は下地が平地色) なので、そのまま使うと**街を塗ったのか平地を
塗ったのか画面で判別できない**。PNG 書き出しも色ではなく**地形 index を R チャンネルに
載せる** (色だと往復で潰れる)。

ドット絵エディタは**マップ編集画面 (`/admin/map`) のタブ**に置く。地図に置いてみて絵を
直す、の繰り返しになるので、別画面に分けると行き来が煩雑になる。

**開いた直後もその地形の代表色でべた塗りした状態にする。** 全画素が透明だと市松模様しか
出ず「壊れている」ように見える (実機で確認)。地形やおおきさを変えたときも同じ。

### 保存先と、権威の一致

編集した地図とドット絵は**主管理者の PDS の 1 レコード**に置く (`world.map` / `world.tileArt`)。
`config.flags` 等と同じで、**全環境・全ユーザーが同じ 1 か所を見る**必要があるため。

**移動判定は edge が権威**なので (`battle-resolver` の `terrainAt`)、edge も同じレコードを
読む。web だけが編集後の地図を見ていると「画面では歩けるのにサーバーが弾く」=
**プレイヤーがその場から動けなくなる**。

- edge は**リクエストごとには読まない**。isolate ごとにキャッシュし TTL 5 分。
  PDS の読み取りは書き込み点数を消費しないが、毎リクエストの往復はレイテンシに乗る
- edge の読み込みは**必ず `ctx.waitUntil` に載せる**。投げっぱなしにすると、リクエストが
  同期的に return した瞬間 (CORS preflight の OPTIONS が該当) に I/O コンテキストごと
  捨てられ、promise が**reject もせず settle しない**。`.catch()` も走らないので警告すら
  出ず、読み込み中フラグがラッチされたままで**その isolate は二度と読み込まない**
  (workerd で実測)
- edge も web も**リクエストは待たせない**。読めるまでは同梱の地図 (生成そのまま) に倒れ、
  それも無ければノイズ生成に倒れる。どの段でも「編集前の世界」として一貫している
- 読み込みに失敗しても握り潰す。手編集が読めなくても遊べる状態を保つ
- 地図の gzip は 27 KB (base64 で 37 KB)。レコードに収まるので blob にはしていない

### 街は画像では表せない — 別の差分で持つ

地形は 1 タイル 1 バイトで済むが、**街は名前を持ち、店の品揃えも座標から導出される**。
地図に「街」パーツを置いただけでは **`townAt` が null のまま**で、
**名前も店も宿 (全回復) も ちずのかけら も無い、通れるだけのマス**にしかならない (実測)。

そこで街は `TownOverride { x, y, name? }` の差分として、地形の画像と**同じレコードの
別フィールド**に持つ。`name` が無ければその座標の街を消す。動かす = 元を消して新しい
座標に足す。`region` は座標から導出するのでエディタに書かせない。

**エディタは地形と街を必ずセットで動かす。** 地形だけ「街」にすると名前の無いマスになり、
街データだけ足すと地形が海のままの街ができる。どちらも片方だけでは壊れる。

**店の品揃えは編集しない (今は)。** `townShopStock` が街の x/y をシードにした純関数なので、
足した街にも自動で並ぶ (#565 の地域段階化もそのまま効く)。裏を返すと
**街を 1 タイル動かすと品揃えが全部変わる**。品揃えを直接編集できるようにするのは
お店エディタ (#422) の担当。

### パーツは増やせる / 通行可否を自分で持つ

「縦の橋」のように**通行判定は既存と同じで絵だけ違う**ものを足せるよう、
パレットの index 1 つを **パーツ** として持つ:

```ts
WorldPart { terrain: string; name: string; walkable?: boolean }
```

- **絵は index ごと**。地形 id で引くと、同じ地形のパーツが全部同じ絵になってしまう
  (よこの橋とたての橋が区別できない)
- **引くのは `partArtFor(index, terrain)` に一本化する。** 絵のキーは元々「地形名」
  だったので、index キーへ移したあとも**古い保存が残っている**。編集画面と描画側で
  探し方が違うと「地図には出るのに編集画面では SVG に戻る」という食い違いが起きる
  (実際に起きた)。`part:N` → 地形名 の順で探し、上書き保存で新しいキーに移る
- `terrain` は遭遇率・危険度など**通行以外**の元になる
- **`walkable` はパーツ自身が持つ。** 地形任せだと「見た目は橋だが通れない飾り」
  「見た目は山だが抜けられる隘路」が作れない。省略時は地形から決まる
- 移動判定は **`isWalkableAt(x, y)`** を通す。`isWalkable(terrainAt(x, y))` を直に
  書くとパーツ側の指定を読み落とし、「見た目は橋なのに渡れない」が起きる。
  **web と edge の両方が同じ関数を使う** (移動判定はサーバーが正)
- 既定の 8 種は index 0〜7 に固定。**並びを変えない**
- **地図を読み直してもパーツを消さない。** `setWorldMap` に `parts` を渡さないときは
  今のパーツを保つ (`loadStaticWorldMap` は渡さない)。既定へ戻していたため、
  増やしたパーツが**地図の読み直しで一覧から消えた**。完全解除 (`setWorldMap(null)`) の
  ときだけ既定に戻す
- **絵タブの保存でもパーツ (地図レコード) を書く。** 絵だけ保存してパーツが消えると
  原因を追いようがない

## 6.8 モンスターはレコードで差し替えられる (#419 / #537)

`MONSTERS` はコード直書きで、リポジトリが公開なので**未実装の敵まで手の内が見える**。
管理者 PDS の `world.monsters` レコードで差し替えられるようにした。

- **レコードが正。ソースは書く場所ではない** (オーナー方針)。同梱の一覧
  (`monster-roster.ts`) はフォールバックとテストの土台であって、**新しい敵・調整済みの
  値をそこへ書かない**。エディタで保存すればレコードが一覧を丸ごと差し替える
- 移行手順: エディタを開く (同梱の一覧から始まる) → 保存 → 以後レコードが正。
  レコード運用が安定したら同梱の中身を汎用プレースホルダへ縮める (#537 の最終段)。
  読めない/壊れていてもフォールバックで戦闘は続く
- **参照を保ったまま中身を差し替える**。`MONSTERS` / `MONSTERS_BY_ID` は 14 箇所以上から
  import されているので、呼び出し側は無変更。`MAX_POPULATED_TIER` は ESM の live binding
- **edge も読む** (戦闘計算の権威)。web だけが編集後の敵を見ていると強さも XP も食い違う
- **壊れた 1 体で全体を落とす** (部分適用しない)
- **tier1 が 3 体を下回る差し替えは拒否** (プールが痩せると遭遇の多様性が壊れるため)
- **プールが空でも移動は殺さない**。`summonMonster` は空の帯を**近い下の帯へ繰り下げて**
  遭遇を成立させ、edge の `handleMove` は遭遇の失敗を握って**移動だけは通す**
  (敵が出ないまま歩ける、に倒す)。「データが壊れていたら 500 で一歩も動けない」は
  検証で防ぐ緩和策ではなく、それ自体がバグ
- `hp` はレコード経由でも必須 (書き忘れの導出フォールバックを到達不能に保つ規律と同じ)
- 能力は id の列挙にとどめる (#537 論点 1-a)。実装は core に残す
- **tier7/8 (魔王の城) の敵は移行を急がない** (#542 の城の有効化と一緒に)

## 6.9 NPC (#425)

マップに置ける「話しかけられる人」。DQ の作法で **タイルを 1 つ占め、歩いてぶつかると
会話が始まる** (移動はしない)。

- **移動判定でも塞ぐ** (`isWalkableAt` に組み込み)。web と edge の両方が同じ一覧を読む —
  片方だけだと「画面では人がいるのにサーバーは素通りさせる」食い違いになる
- 保存先は管理者 PDS の `world.npcs`。壊れた 1 人で全体を落とす。
  **同じマスに 2 人は立てない** (ぶつかったときどちらと話すのか決められない)
- 絵はドット絵 (`npc:<id>`)。無ければ代替の人形。エディタから「絵をかく」で描ける
- エディタ (`/admin/npcs`) は置き場所の落とし穴を警告する:
  歩けないマスの上 (だれもぶつかれない = 話せない) / 街のマスに重なる (入口を塞ぐ)。
  保存は拒否しない (意図的な配置がありうる)
- フラグ制御 (進行で出現・退場) は #426 のフラグ管理とセットで続き

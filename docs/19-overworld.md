# あおぞらワールド (2D オーバーワールド) 仕様書案

status: **draft v2 — 主要判断済み** (2026-07-17 オーナー回答反映)。細部は実装 PR で詰める。

ブルスコンの試練 (docs/18) を「メニューから挑む」形から、**2D の広域マップを
一歩ずつ探索する**形へ拡張する。移動・遭遇・採集・街での買い物をゲームループの
中心に置き、戦闘は docs/18 のエンジン (v2: MP/ため予告/やくそう) をそのまま使う。

## 1. ワールド

- **大きさ**: 1024 × 1024 タイル。**トーラス** (端は逆の端に接続。x, y とも mod 1024)。
- **生成**: 固定のグローバルシードから**決定的に手続き生成** (packages/core に純関数
  `tileAt(x, y): Terrain`)。全ユーザーが同じ世界を見る。1M タイルを保存しない —
  表示のたびに計算する (16×16 = 256 タイル/画面なので計算コストは無視できる)。
  - ノイズは**周期格子** (格子点 index を mod 1024) で作り、トーラスで継ぎ目が出ない
    ようにする。標高 + 湿度の 2 チャンネル + バイオーム規則で地形を決める。
- **地形** (8 種):

  | 地形 | 通行 | 遭遇率/歩 | アイテム率/歩 | 備考 |
  |---|---|---|---|---|
  | 平地 | ○ | 低 (5%) | 3% | 基本地形 |
  | 林 | ○ | 中 (10%) | 5% | |
  | 森 | ○ | **高 (20%)** | 8% | 実入りも危険も大きい |
  | 池 | ✕ | - | - | 将来: カヌー/船で通行可 |
  | 川・海 | ✕ | - | - | 将来: 船で通行可 |
  | **橋** | ○ | 低 (5%) | - | 川を渡る。街道の要所に決定的に配置 |
  | 山 | ✕ | - | - | 将来: 飛行船で通行可 |
  | 街 | ○ | 0 | - | なんでも屋。安全地帯。平地の上に描画 |

  タイルのビジュアル案は `docs/overworld-drafts/tiles.html` (SVG、v2 でオーナー確認)。
  未踏は「霧」(雲がかった青灰) で表現。**プレイヤーはユーザーの実アバター +
  ジョブ装備 (components/job-equipment.tsx) をマップ上にそのまま描画**する。

  (率は初期値。BATTLE_TUNING 同様に WORLD_TUNING として core に集約し調整可能に)
- **街**: 128×128 の各リージョン (8×8 = 64 個) に 1 つ、平地の上に決定的に配置
  (~64 街)。初期位置は原点リージョンの街。
- **地域性**: リージョンごとに**危険度** (原点からのトーラス距離 + ノイズ) を持ち、
  出現モンスターの tier とプールが変わる。バイオーム別テーブル
  (森=植物/獣系、水辺=大蛇、山麓=ゴーレム、夜鴉・鬼・竜は高危険度のみ、など)。
  モンスター図鑑は既存 9 種から始め、地域固有種を追って足す。

## 2. 画面と移動

- **ビューポート**: 16×16 タイルのみ表示 (プレイヤー中央固定、世界がスクロール)。
  モバイル幅 ~360px で 1 タイル ~22px。描画は SVG (絵文字/簡易シンボル + 色) で軽量に。
- **移動**: 1 タップ = 1 マス (十字キー UI + スワイプ)。トーラスなので座標は自動 wrap。
- **未踏の霧**: 訪れたタイル + 現在のビューポートのみ描画。
  **地図のかけら**を入手すると、そのリージョン (128×128) の俯瞰ミニマップが解禁される
  (64 リージョン = 64bit のビットフィールドで管理)。かけらは移動時の発見物 or
  戦闘勝利ドロップ (低確率) で入手。

## 3. 経済 (オーナー決定済み)

- **移動コスト: 1 歩 = 1 あおぞらパワー** (決定 2026-07-17)。「1 日 100 投稿する人は
  ザラに居る」= ヘビーユーザーほど遠くまで歩ける設計。投稿がそのまま行動力になる。
- **なんでも屋** (街の上で開ける): あおぞらパワー + 素材で購入。
  - **品揃えは街ごとに違う** (決定)。基本は「その街の周辺リージョンに出る
    モンスターに効く装備」を売る = 地域のモンスターと店がセットで意味を持つ。
    装備には**特効** (species / バイオーム別のダメージ補正) を持たせる。
  - **武器/防具**: 戦闘値に加算 (atk/def/agi/int/luk への補正) + 特効。装備レコードは
    `app.aozoraquest.equipment/self` に保存。docs/18 Step2 の実現。
  - **道具**: やくそう (素材ドロップの補完)、地図のかけら、将来はカヌー/船/飛行船。
- gamble 系ジョブ (低 atk・低 int) は装備で火力を補う前提 (docs/18 の既知課題の回収先)。

### 街の名前

64 の街すべてに固有名を付ける (決定)。core に日本語の名前テーブルを持ち、
リージョン番号 → 名前を固定対応 (例: 「そらみの街」「かぜまちの宿場」「しおさいの湊」…)。
バイオーム/危険度に合わせた命名 (水辺は湊・岬、森は杜・木立、高危険度は砦・関 等) で
世界の手触りを出す。名前はミニマップ・街画面・店のヘッダに表示。

## 4. 不正防止 — Worker 乱数オラクル

遭遇・アイテム発見・(そこから始まる) 戦闘のシードを**クライアントに選ばせない**。

- **方針: 移動も戦闘もサーバー権威** (オーナー決定 2026-07-17)。クライアントは
  入力 (移動方向 / 戦闘コマンド) を送るだけの薄いレンダラーで、判定はすべて
  Worker が行う。バトルエンジンは packages/core の**純関数** (seed 決定的・state は
  JSON 化可能) として実装済みなので、**Worker が同じ core を import してサーバー側で
  resolveTurn を実行する** (web と worker のコード共有 = ロジックの二重実装なし)。
- **構成**: 既存の Cloudflare Worker (アプリ配信) に `/api/world/*` を追加。
  per-DID の **Durable Object** が歩数カウンタ・現在位置・進行中の BattleState を保持。
- **移動プロトコル** (**1 歩 = 1 リクエスト**。シードのまとめ発行 (バッチ) は、先読みで
  「次の歩の遭遇が事前に分かる → 止まって回避」というチートを許すため**採らない**):
  1. クライアント: `POST /api/world/step { dir }`
  2. Worker (DO): 位置は DO 側が正。歩数カウンタを進め `seed = HMAC(secret, did|counter)`
     を生成し、地形 (`tileAt`) と遭遇/アイテム判定をサーバー側で解決。
     結果イベント (遭遇開始 / アイテム入手 / 何もなし) と新しい座標を返す。
- **戦闘プロトコル** (遭遇したら DO が BattleState を保持し、**コマンドを毎ターン送る**):
  1. クライアント: `POST /api/world/battle { command }` (たたかう/とくぎ/ぼうぎょ/やくそう)
  2. Worker (DO): 保持中の BattleState に resolveTurn を適用し、表示用の
     イベントログ + HP/MP/残やくそう + outcome を返す。**クライアント側では戦闘を
     解決しない** (コマンド選択の結果を偽れない)。
  3. 決着時: Worker が**署名付きの結果** (outcome / drops / XP / counter) を返し、
     クライアントはそれを battle レコード (PDS) に保存 → 勝敗・ドロップの改竄不可、
     後から検証可能。
  - レイテンシ (エッジで ~50-150ms) は移動アニメ・戦闘演出の楽観表示で隠す
    (通行可否はクライアントも `tileAt` で事前計算できる)。
- **担保されること**: シードの先読み・引き直し不可、遭遇回避・戦闘結果・ドロップの
  改竄不可、位置の改竄不可。**担保しないこと**: 見た目だけの改造 (報酬に繋がらない)。
- 位置・歩数・所持は PDS レコード (`app.aozoraquest.world/self`) にも保存し、
  Worker の counter と突合できるようにする (監査線)。

## 5. データ (PDS)

| record | rkey | 内容 |
|---|---|---|
| `world` | self | x, y, 歩数残 (案A の両替分), 解禁リージョン bitfield, 乗り物フラグ |
| `equipment` | self | 装備中の武器/防具/道具 |
| `purchase` | tid | 購入履歴 (パワー消費の記帳。cardDraw/battle と同型) |
| `battle` | tid | 既存 + `worldSeedSig` (Worker 署名) を追加 |
| `pickup` | tid | フィールド採集の記帳 (item, 座標, seed, 署名) |

パワー式は `viaPosts − userMessages − cardDraws − battles − purchases − steps両替` に拡張。

## 6. 試練 (現行) との関係

- /spirit の「試練の間」は**ワールドへの入口**に置き換える (ブルスコンが案内役)。
- 遭遇戦闘は現行エンジンをそのまま使用 (コマンド/MP/やくそう/ため予告は不変)。
  敵 tier は「選ぶ」のではなく**地域で決まる** (難易度自動化の完成形)。
- **敗北時は最寄りの街に戻される** (決定 2026-07-17)。追加のデスペナは無し
  (消費済みパワーと歩いた分が実質のコスト)。

## 7. 段階実装 (PR 分割)

1. **PR-W1** core: 決定的ワールド生成 (`tileAt` / 街配置 / 危険度 / WORLD_TUNING) + テスト
   (トーラス継ぎ目・通行判定・街の数・分布の統計)
2. **PR-W2** UI: ビューポート描画 + 移動 (この段階はパワー消費なしの「散歩プレビュー」を
   dev だけで確認) + world レコード
3. **PR-W3** Worker: DO (位置 + 歩数カウンタ) + 移動 API + 遭遇/採集判定 + パワー消費配線
4. **PR-W4** Worker: **サーバー権威バトル** (DO が BattleState 保持、コマンド API、
   署名付き結果) + クライアントの試練 UI を薄いレンダラーに置換
5. **PR-W5** 地図のかけら + リージョンミニマップ
6. **PR-W6** 街・なんでも屋・装備 (戦闘値への反映) ← docs/18 Step2 を吸収
7. **PR-W7 (将来)** 乗り物 (カヌー/船/飛行船) と水路/山越え

## 8. 判断ログ (2026-07-17 オーナー回答)

1. **移動コスト**: 1 歩 = 1 パワー厳守 (ヘビーユーザーは 1 日 100 投稿 = 100 歩)。
2. **敗北**: 最寄りの街戻りのみ。
3. **店**: 街ごとに品揃えが違う。地域モンスターに効く (特効) 装備を売る。
4. **街に固有名を付ける** (§3)。
5. **Durable Objects の課金試算** (2026-07 時点の CF 料金で):
   - DO は **Workers Free プランでも利用可** (SQLite-backed)。無料枠は
     リクエスト ~300 万/月・compute 約 39 万 GB 秒/月・ストレージ 5GB
     (Free プランはストレージ課金なし)。
   - 本機能の負荷: 1 歩 = 1 パワー = 1 投稿相当なので、ヘビーユーザーでも
     ~100 歩/日 = 100 リクエスト/日/人。戦闘もサーバー解決 (1 ターン 1 リクエスト)
     で、遭遇 ~10 戦/日 × ~10 ターン = +100 リクエスト/日/人。**合計 ~200/日/人**。
     アクティブ 100 人でも 2 万 req/日 ≈ 60 万/月 = **無料枠 (~300 万/月) の 20%**。
     DO はハイバネーションで待機中は compute 課金されず、保持するのはカウンタ +
     座標 + 進行中 BattleState (~1KB)。
   - **結論: 想定規模では追加課金 $0** (無料枠内)。有料プラン ($5/月) でも
     込み枠が桁違いに大きく増額なし。アカウントのプラン種別だけ実装時に確認する。

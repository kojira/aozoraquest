# #673 地図を入手したことを読めるまで表示する

## 原因と範囲

ユーザー報告は「新しい街に到着しても地図入手で何も起こらなかった」。本人が訪れた街や進捗は未取得で、同じ原因だったとは断定しない。

現在dev f9a3ab8のWorldは、edge `handleMove` の `townArrival` に対して `recordTownArrival` を呼び、周辺3×3リージョンが増えた場合のみ入手文を一時 `notice` に設定する。一方、続く通常移動応答は `setNotice(null)` にする。VirtualStickは170ms間隔で歩き続けるため、地図が保存されても入手文を読む前に消す。

実World＋VirtualStick＋handleMove（PDS/外部通信のみ隔離）で、フィールド街・ゲート経由の内部街どちらもregionsが1→9に保存される一方、押しっぱなしでは獲得を確認する窓が無いことを回帰テストで確認した。

実devはindex-DjGIWSx2 / world-sI5y0r1-を配信し、townArrival/既存入手文とdev edge接続先を保持。edge最新配備41627402（2026-09-14）は#664以降のもの。webのみ変更した#672後に古いedgeへ戻った証拠はない。認証が必要な実ゲームAPIは呼ばず、実ユーザーの進捗・実PDSには書き込まない。

## 修正する契約

- 実際にregionsが増えたときだけ、既存DialogueWindowに到着＋入手の1文を表示。通常の読了タップで閉じる。親がこの小さなUX変更を承認済み。
- 読了までmoveガードを立てる。VirtualStickを取り外して既存の停止cleanupで反復/捕捉ポインタを破棄し、閉じた後は新しい操作から歩ける。キーボードの押しっぱなしrepeatも新しい押下まで再開しない。
- 同時NPC/シナリオ窓を重ねない。店タイルへ直接着くゲートでも店の描画は入手文の読了後にする。報酬・地域計算・visitedTowns・保存形式・保存失敗の既存扱いは変えない。
- 初訪問でも3×3が既解禁ならgained=false。従来到着文だけで、入手を偽らない。
- 地図は従来どおりフィールドの「ちず」から見る。内部マップのローカル座標を世界地図へ重ねない。入手時に地図を自動で開く変更はしない。
- 起動/復帰時に新しい獲得イベントを作らず、保存済regionsを読み直す。通知自体は永続化しない。

## 受入と確認

`apps/web/e2e/world-town-arrival.spec.ts` は実Worldと実handleMoveを使用。実service/PDSは全て遮断し、既存tutorial test entry/隔離transportを使用する。

1. 通常街/ゲート街で保存regions=9、visitedTowns=到着街、読了まで窓を表示。
2. スティックを3周期超押したままでも移動1回だけ。窓を閉じた後に旧入力が再開せず、新しいキー操作で移動する。
3. リロード後も地図が残り、獲得窓を再生成しない。フィールドではコマンド→ちずを実際に開ける。内部では従来どおりちず入口を表示しない。
4. 周辺既解禁・訪問メモ空の街への入場でも入手窓を出さない。
5. 保存503でも窓を閉じて歩ける。通知ループ/追加付与処理なし。

回帰は修正前2失敗、修正後2成功。390pxで獲得文の非重複を目視確認。初回テストセットアップではbrowser専用env依存moduleの直接importを修正、最初のgreen確認ではテストのCSS selectorを実コンポーネントのpane名へ修正した（製品の修正追加ではない）。実機Safariとユーザー本人の実到着状況は未確認。

最終確認: web typecheck/build、web 431 tests、edge 270 tests、web lint（既存24 warnings/0 errors）、既定Playwright設定で上記2 tests、git diff --check成功。edge testは指定引数がscriptのvitest filterにならず全270件が実行されたため、その成功結果を使用し再実行していない。変更はweb表示とブラウザ回帰・本文書のみ。独立レビュー、CI、マージ/配備は後続ゲート。

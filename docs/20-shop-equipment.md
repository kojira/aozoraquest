# なんでも屋と装備品 (W6)

あおぞらワールドの街に「なんでも屋」を置き、消耗品と装備品を売る。
本番リリース必須要件 #5「街ごとに特色のあるアイテムを買えないと移動する
モチベーションがわきません」(オーナー、2026-07-17) と #6「アイテムの調整」に
対応する。docs/19 (ワールド) と docs/18 (バトル) の続き。

## 判断ログ (オーナー決定、2026-07-17)

- **装備は 2 層構造**: 共用装備 (ナイフ・ぬののふく等、誰でも装備可) +
  ジョブ制限装備 (手裏剣・忍者刀・騎士の盾・魔法の杖等)。
  → 2026-07-18 に **4 層 + 適性マトリクス** へ更新 (後段の「4 層構造」参照)。
- **「誰でも装備可 + ジョブ一致ボーナス」案は却下** —「ジョブを希薄化させないで。
  そもそも転職という選択肢があるのだから、アイテムのために転職するモチベーションが
  発生しやすくなります」。転職は投稿行動の解析で決まるため、欲しい装備が
  **投稿スタイルを変える動機**になる (ゲームと投稿の接続はこのプロダクトの核)。
- **クエスト機能でアイテム交換するルートも作る** —「欲しいジョブの装備を交換です」。
- 帰還アイテム「そらのはね」は実装済み (docs/19)。W6 で全店の基本枠に並べる。

## 経済 — 「購入」ではなく「制作」(オーナー決定 2026-07-18)

- 入手は**制作依頼**: パワー n + 素材 m 個をわたして作ってもらう (素材が必要な
  時点で購入でなく制作、の語彙。UI も「つくってもらう」)。
- **強化値 −1〜+10** (オーナー決定 2026-07-18)。制作ロールは **−1〜+5** で、
  luk が下限を引き上げる (床 = floor(luk×0.05)、上限 +3。luk 20 で失敗作 −1 を
  引かなくなる —「うんが高いほど下振れしにくい」の設計言語)。効果は主効果
  (いちばん大きいボーナス) に +N。「ナイフ+3」表記、+5 は「名匠」扱い。
- **+6 以上は合成 (きたえる) のみ**: 同じアイテム・同じ強化値 2 つ → 1 つ上。
  +7 には +6 が 2 つ (= +5 換算 4 つ)、+10 には 32 個 — **過剰なアイテムを燃やす
  指数的シンク**。合成は +5 未満でも可能 (余り物の活用でさらに燃える)。
- **強化値はレコードを増やさず導出**: 制作 1 件 = 1 craft レコード、強化値 =
  hash(rkey) + 制作時 luk。合成 1 件 = 1 forge レコード (消費した 2 個体の rkey を
  記録 — 集計が存在・同 itemId・強化値一致を検証し、二重消費やレベル飛ばしの
  偽造レコードは黙って無効)。自己申告フィールドは持たない (書いても無視)。
  ※ これは**正規クライアント間の整合性保証**であり改竄耐性ではない — rkey も
  luk もクライアント選択のため総当たりで高強化値を選べる。最終的な正は W3 の
  サーバー権威 (「実装より盛らない」原則により明記)。
- **素材のひきとり** (オーナー決定 2026-07-18「素材を燃やしてあおぞらパワーに
  変換する仕組みも必要。無限ループ防止のためレートは低め」): 5 個 = パワー 1
  (SALE_TUNING)。対象はモンスター素材のみ (消耗品は対象外)。レート根拠:
  1 戦 = パワー 1 で素材期待値 ~1.2 個 → 1 パワー投資の回収 ~0.24 パワーの
  強い赤字でループ不成立 (最悪ケースでも赤字であることをテストで固定)。
  記帳は sale レコード (craft コレクション、素材燃焼として在庫減算) +
  power/self の salePowerEarned 累積。残高式は
  `viaPosts − userMessages − cardDraws − battles − craftPowerSpent + salePowerEarned`。
- 集計は 500 件上限 (battle と同型の割り切り)。超過分の素材・パワー消費は
  再スキャン時に数え漏れる — W3 で解消。
- W6c 判断記録: 装備 luk が制作 luk に乗る自己強化ループは**意図した仕様**
  (運型ジョブ = 名品を作ってもらえる職、の延長。床上限 +3 で有界)。
- 支払いの記帳: craft レコード + power/self の `craftPowerSpent` **累積額**
  (制作費は品ごとに違うため件数でなく額)。残高式は
  `viaPosts − userMessages − cardDraws − battles − craftPowerSpent`。
  素材の消費は craft レコードの集計で在庫から差し引く。
- 価格の正は `packages/core/src/equipment.ts` (W6a 実装値: 共用初級 パワー 4〜8 +
  素材 1〜2 / カテゴリ初級 10+2 / 専用中位 20+4 / 専用上位 40+6。初期案の
  「初級 10〜15+3」より入口を安くした)。素材の**種類**は店ごとに決定的に決まる
  (`shopMaterialFor` — その地域で狩って買うループ)。最終値はアイテム調整 (要件 #6)
  で sim + オーナー実機により確定。

## 装備品

### スロットと効果

- **3 スロット: 武器 / 防具 / お守り**。
- 武器 = 攻撃系ステータス (系統ごとに対象が違う)、防具 = def/maxHp、
  お守り = 特殊効果 (回避+、ドロップ率+、MP 消費−、species 特効など)。
- 数値は **ブレンド・レベル補正の後に平坦加算** (playerCombatant に equip 引数を
  追加)。低ステータスほど相対効果が大きく「装備で差をつける」が実現する。
- 規模感: 初級 +4 / 中位 +8 / 上位 +14 (実装時に sim で tier 勝率バンドを再実測し、
  必要なら tier 係数側も同時調整 = アイテムの調整)。

### 4 層構造 + 装備適性マトリクス (オーナー確定 2026-07-18)

1. **共用** (誰でも): ナイフ、こんぼう、たびのつるぎ / ぬののふく、かわのよろい、
   たびのマント。「専用品が見つかるまで装備ゼロ」の空白を防ぐ下支え。
2. **カテゴリ品** (装備適性マトリクスで判定): 斧・盾・短刀・杖・運具 (武器) /
   重装・軽装・ローブ (防具)。**意匠のない汎用名のみ** (忍者刀のような
   ジョブ意匠の品はここに置かない — 遊び人が忍者刀を振るのは違和感、の指摘)。
3. **ジョブ専用・中位** (+8): 忍者刀、神楽鈴、騎士の盾、魔法の杖…
4. **ジョブ専用・上位** (+14、特色枠): 影縫いの手裏剣、大神楽の鈴、月夜の琴…

装備適性の要点 (`JOB_EQUIP_KINDS`、正は packages/core/src/equipment.ts):
- **戦士は杖・運具・ローブ以外ぜんぶ装備できる** — MP が低い代わりの広適性
  (MP 特性の裏返しの職特性)。隊長・冒険者・匠も広め、巫女・予言者など専業系は狭め。
- **ジョブ専用品 (jobOnly) はマトリクス不問** — 自ジョブなら装備できる
  (神楽鈴に鈴カテゴリは要らない)。
- 全 16 職に専用武器が中位・上位の 2 本ずつ (計 32 本。テストで固定)。
- 他ジョブの装備も**購入・所持は可能** (転職準備 / クエスト交換の材料)。
  店では「(要: 吟遊詩人)」のように表示 — 装備できない品が見えること自体が誘い。

### 記録 (PDS)

- 所持装備 = `craft` レコード (制作) + `forge` レコード (合成、消費 rkey つき) の
  検証済み集計。素材在庫 = 戦闘ドロップ − 使用 − 敗北ロス − 制作消費。
- 装備中 = `gear/self` レコード。**強化値は直書きせず craft/forge の rkey を参照**し、
  集計が再導出した値を使う (W6c 契約 — 直書きを信用すると導出方式の意味が消える)。
- 在庫・支払いの正は W3 で DO に移す (docs/19 既定路線)。それまでは
  クライアント記帳 (dev プレビュー限定)。

### 専用装備の弱点補完 (オーナー指摘 2026-07-18)

専用品は原則「支配ステータスを盛る」だが、**支配ステを盛っても職の構造的弱点が
埋まらない場合は複合効果で補完する**。将軍がその実例 —「将軍アイテム手に
入れてもよわくない?」のとおり、こうげき単盛りではフル装備でも tier3 45% と
全職で唯一破綻していた (弱点は火力でなく耐久)。采配・軍神の大太刀に
「指揮官は兵に守られる」フレーバーで まもり・さいだいHP を付け、65% に是正
(全職 band 65〜99%。回帰テストで下限 55% を固定)。

### 装備込みバランスの実測 (W6a 時点、アイテム調整の基礎数値)

フル装備 (専用上位 + 系統防具 + ペンダント) の tier3 勝率 (jobLv8/plLv15):
bard 33%→72% / shogun 17%→45% (弱ジョブ救済が機能)。一方 miko 85%→98%、
warrior 88%→99% と上位ジョブは天井を超える — **装備前提の敵側再調整が
「アイテム調整」の主題** (装備なし = 挑戦的、フル装備 = 快適、の帯を作る)。

## 街の品揃え (53 街を手作りしない)

**(危険度, 周辺地形, 街 ID ハッシュ) から決定的に生成**する。ワールド生成と同じ
「seed から一意」の原則で、テストで固定できる。

1. **基本枠** (全店共通): やくそう / そらのしずく / そらのはね
2. **地域枠**: danger に応じた tier の共用装備 (辺境ほど強い) — **W6c 以降**
3. **系統枠**: 周辺地形で装備系統が決まる (森 = 弓と葉のお守り / 山際 = 鉱石の
   重装備 / 水辺 = うろこ素材の軽装) — **W6c 以降**
4. **特色枠**: ジョブ専用品の巡回割当 (中位は全店、上位は 1/3 の街のレア枠。
   どちらも**全 16 職の品が世界のどこかに必ず並ぶ**ことをテストで保証) —
   **W6a 実装済み**。**地図を見て「あの街には何があるか」が移動動機**

W6a 時点の生成は「街ハッシュ + 巡回割当」のみ (正: `townShopStock`)。
W6b 実装済み (2026-07-18): 店 UI (街で「なんでも屋」ボタン → 制作モーダル)、
craft レコード + craftPowerSpent、品質導出、名匠演出。装備の着脱 (gear/self) は
W6c。消耗品の制作は未対応 (ドロップのみ)。
なお装備で上位ジョブの tier3 が一時的に作業化する窓 (W6b 購入開放〜アイテム調整
完了の間) は dev プレビュー限定と割り切る。

## ギルドと旅の目的 (オーナー方針 2026-07-17)

街には**ギルド**がある。なんでも屋が「装備の供給」なら、ギルドは**旅の目的の供給**。

- **地図のかけら**: はじまりの街のギルドで、最初の 1 枚を**必ずもらえる**
  (チュートリアル動線)。以降のかけらは各地のギルド・討伐報酬・特色枠で入手し、
  地図の開示範囲が広がる (W5 の開示機構と接続。プレビュー期の全図開示は
  かけら実装時に「持っている範囲だけ表示」へ移行)。
- **討伐クエスト**: ギルドの掲示板に「◯◯を n 匹討伐」が数件並ぶ。報酬は
  パワー・素材・装備・地図のかけら。討伐数は battle レコード (monsterId 別) の
  集計で判定できるため、既存の記録機構がそのまま使える。地域のモンスターを
  狩る理由 = その街に滞在する理由になる。
- **住人のヒント**: はじまりの街の住人が**次の街の方向をそれとなく教えてくれる**
  (「東の橋を渡った先に、たしか村があったはずじゃ」)。ヒント文はワールドデータ
  から決定的に生成できる (最寄りの街への方位 + 途中の目印地形)。手取り足取りの
  矢印ではなく「それとなく」がトーン。
- **NPC パーティー (将来)**: いずれギルドで NPC を雇ってパーティーを組んで移動
  できるようにする。戦闘エンジンは 1 対 1 前提なので、複数人戦闘への拡張は
  独立した設計題目として別 doc で扱う (ここでは方針の記録のみ)。

## クエストでの装備交換 → リアルな依頼への誘導

- 依頼クエスト (掲示板) の報酬にアイテムを添付できるようにする。
  「巫女の神楽鈴と吟遊詩人の琴を交換してほしい」のような依頼が立つ。
- **段階導入** (オーナー決定 2026-07-18): 初期はリアル依頼への誘導をしない。
  人口が増えてアイテム交換の文化が広がってから、下記のイラスト依頼
  パイプラインを開く。

### ギルドのイラスト依頼パイプライン (オーナー設計 2026-07-18)

ゲーム内アイテムのイラストを、コミュニティの創作で集める **2 段階構成**:

1. **ギルド (システム) が「アイテム X のイラスト 1 枚」の依頼を出す**。
   1 アイテムにつき最大 3 枚 — **1 枚ずつ別の依頼**として出す (3 枚まとめて
   納品ではない)。
2. **受注者 = アートディレクター役**。ギルド依頼を受けたプレイヤーが、リアル世界の
   住人 (絵を描ける人) に依頼クエストでさらに発注する。
   **同じアイテムの依頼は同じ人が受けられない** (オーナー決定 2026-07-18) —
   別の審美眼による選定で多様性を出し、クエストの独り占めを防ぐ。
3. **品質判定は受注者が行う**。酷いイラストは却下できる。運用は既存クエストと
   同じ「やり直し依頼 → 再提出」を先に挟み、却下は最終手段 (描き手が丸損になる
   即時却下は紛争の種)。受注者自身にも 1 枚納品ごとの完了報酬を用意する —
   キュレーション労働への対価。
4. **描いた人には 100 あおぞらパワー**。パワーが「投稿活動」に加えて
   **創作労働にも裏付けられた通貨**になる。

システム要件:
- **イラスト投稿フォーム**: 画像 (PDS blob) + 対象アイテム + **ゲーム内表示の
  非独占許諾チェック** (著作権は作者に残る) を提出レコードとして書く。
- **©️ 表示**: ゲーム内でイラストを表示する箇所には常に「©️ 作者 handle」を添える。
- **報酬付与の権威**: パワー残高は自己レコード集計のため、自称 +100 は偽造可能。
  付与は**管理者 (ギルド) 側 PDS の付与レコード** (受領者 DID + 対象イラスト) を
  残高計算が参照する形にする (他人のリポジトリは偽造不能の原則)。W3 サーバー
  移行後は DO でも可。
- **モデレーション**: 公開表示される画像なので、通報 → 管理者非表示の経路を
  初期から用意する。
- 譲渡は **譲る側が自分の PDS に譲渡レコード (相手 DID + item id) を書く**。
  他人のリポジトリは偽造できないため、受け取り側の集計が相手のレコードを参照する
  ことでサーバーなしでも検証可能。二重譲渡 (同じ 1 個を 2 人に譲る) の検証は
  集計側で行い、最終的な正は W3 の DO。

## UI

- 街タイルに入るとどうぐ列に「🔨 なんでも屋」ボタン → 制作モーダル
  (品揃え / 値札 = パワー+素材 / 所持数と最高強化値 / つくってもらう (確認つき) /
  きたえる / 装備できないものは (要: ジョブ名) + 確認時に「いまは装備できないけど」)。

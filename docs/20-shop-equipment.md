# なんでも屋と装備品 (W6)

あおぞらワールドの街に「なんでも屋」を置き、消耗品と装備品を売る。
本番リリース必須要件 #5「街ごとに特色のあるアイテムを買えないと移動する
モチベーションがわきません」(オーナー、2026-07-17) と #6「アイテムの調整」に
対応する。docs/19 (ワールド) と docs/18 (バトル) の続き。

## 判断ログ (オーナー決定、2026-07-17)

- **装備は 2 層構造**: 共用装備 (ナイフ・ぬののふく等、誰でも装備可) +
  ジョブ制限装備 (手裏剣・忍者刀・騎士の盾・魔法の杖等)。
- **「誰でも装備可 + ジョブ一致ボーナス」案は却下** —「ジョブを希薄化させないで。
  そもそも転職という選択肢があるのだから、アイテムのために転職するモチベーションが
  発生しやすくなります」。転職は投稿行動の解析で決まるため、欲しい装備が
  **投稿スタイルを変える動機**になる (ゲームと投稿の接続はこのプロダクトの核)。
- **クエスト機能でアイテム交換するルートも作る** —「欲しいジョブの装備を交換です」。
- 帰還アイテム「そらのはね」は実装済み (docs/19)。W6 で全店の基本枠に並べる。

## 経済

- **値札は「あおぞらパワー n + 素材 m 個」の 2 部制**。パワーは投稿で湧く一次通貨、
  素材は戦闘ドロップの二次通貨。素材に使い道ができ、戦闘報酬が意味を持つ。
- 支払いの記帳は cardDraw/battle と同じ流儀: 購入 1 件 = `purchase` レコード +
  power/self の `purchases` カウンタ増分。残高式は
  `viaPosts − userMessages − cardDraws − battles − purchases` に拡張。
- 相場観: 初級装備 = パワー 10〜15 + 素材 3 個 (投稿 2 週間分弱)。消耗品は 1〜4。
  最終値は実装時に sim + オーナー実機で調整 (要件 #6)。

## 消耗品ラインナップ

| アイテム | 効果 | 入手 |
|---|---|---|
| やくそう | HP 30% 回復 (既存) | ドロップ / 全店 |
| そらのしずく | MP 50% 回復 (既存) | ドロップ / 全店 |
| そらのはね | 最後に立ち寄った街へ帰還 (既存) | ドロップ / 全店 (安価) |
| いやしのしずく | HP 60% 回復 (やくそう上位) | danger 2+ の街 |
| せいれいのすず | 60 歩のあいだ遭遇率半減 | 特色枠 |
| まものよせのこな | 60 歩のあいだ遭遇率 2 倍 | 特色枠 |

すず/こなの歩数カウントは W3 の DO (サーバー側歩数) と相性が良い。W3 より先に
出す場合はクライアント歩数 (プレビュー限定の割り切り、docs/19 の在庫と同じ)。

## 装備品

### スロットと効果

- **3 スロット: 武器 / 防具 / お守り**。
- 武器 = 攻撃系ステータス (系統ごとに対象が違う)、防具 = def/maxHp、
  お守り = 特殊効果 (回避+、ドロップ率+、MP 消費−、species 特効など)。
- 数値は **ブレンド・レベル補正の後に平坦加算** (playerCombatant に equip 引数を
  追加)。低ステータスほど相対効果が大きく「装備で差をつける」が実現する。
- 規模感: 初級 +4 / 中位 +8 / 上位 +14 (実装時に sim で tier 勝率バンドを再実測し、
  必要なら tier 係数側も同時調整 = アイテムの調整)。

### 2 層構造

**共用装備** (誰でも): ナイフ (+atk 小)、こんぼう、たびのつえ、ぬののふく、
かわのよろい、たびのマント… 素朴な汎用品。全店の基本枠。装備導入時に
「専用品が見つかるまで装備ゼロ」の空白を防ぐ下支え。

**ジョブ制限装備**: 装備可能ジョブを品ごとに明記。
- 系統品 (支配ステータス系統 3〜4 職): 忍者刀 (agi 系)、騎士の盾 (def 系)、
  魔法の杖 (int 系)、戦斧 (atk 系)、幸運のタリスマン (luk 系) …
- **1 職専用の特色品** (転職・交換動機の本命): 月夜の琴 (吟遊詩人)、神楽鈴 (巫女)、
  手裏剣 (忍者)、聖光の大盾 (聖騎士) … 街の特色枠とレアドロップに出る。
- 他ジョブの装備も**購入・所持は可能** (転職準備 / クエスト交換の材料)。
  店では「(要: 吟遊詩人)」のように表示 — 装備できない品が見えること自体が誘い。

### 記録 (PDS)

- 所持 = `purchase` レコード + 戦闘ドロップの集計 − 使用/譲渡 (戦績と同じ集計方式)。
- 装備中 = `gear/self` レコード `{ weapon?, armor?, charm? }` (item id)。
- 在庫・支払いの正は W3 で DO に移す (docs/19 既定路線)。それまでは
  クライアント記帳 (dev プレビュー限定)。

## 街の品揃え (53 街を手作りしない)

**(危険度, 周辺地形, 街 ID ハッシュ) から決定的に生成**する。ワールド生成と同じ
「seed から一意」の原則で、テストで固定できる。

1. **基本枠** (全店共通): やくそう / そらのしずく / そらのはね
2. **地域枠**: danger に応じた tier の共用装備 (辺境ほど強い)
3. **系統枠**: 周辺地形で装備系統が決まる (森 = 弓と葉のお守り / 山際 = 鉱石の
   重装備 / 水辺 = うろこ素材の軽装)
4. **特色枠**: 街 ID ハッシュで決まる 1〜2 品の「この街だけ」— 1 職専用装備・
   species 特効品・すず/こな。**地図を見て「あの街には何があるか」が移動動機**

## クエストでの装備交換

- 依頼クエスト (掲示板) の報酬にアイテムを添付できるようにする。
  「巫女の神楽鈴と吟遊詩人の琴を交換してほしい」のような依頼が立つ。
- 譲渡は **譲る側が自分の PDS に譲渡レコード (相手 DID + item id) を書く**。
  他人のリポジトリは偽造できないため、受け取り側の集計が相手のレコードを参照する
  ことでサーバーなしでも検証可能。二重譲渡 (同じ 1 個を 2 人に譲る) の検証は
  集計側で行い、最終的な正は W3 の DO。

## UI

- 街タイルに入ると場所情報行に「なんでも屋へ」ボタンが出る → 店画面
  (品揃えリスト / 値札 = パワー+素材 / 所持数 / 購入ボタン / 装備できないものは
  (要: ジョブ名))。
- 装備の付け替えは /me またはワールドの「そうび」画面 (W6c で決定)。
- 戦闘値への反映は playerCombatant 経由で試練・ワールド・/me すべて自動追従。
